# Mentor-only reference solution

`reference_solution.cpp` is a complete, working implementation of Floyd-Warshall,
Brute Force, Held-Karp, and Simulated Annealing (Nearest-Neighbor start +
2-opt neighborhood + geometric cooling). It's what generated every
`output_small.json` / `output_large.json` under `../Tests/`.

Do **not** hand this to mentees — it's the answer key. Use it to:
- Sanity-check a mentee's output against exact optimal costs.
- Regenerate/extend test cases if you add more `Test N` folders.

## Build & run

```bash
g++ -O3 -std=c++17 -I <path-to-nlohmann-json-include> reference_solution.cpp -o reference_solution

# mode = "small": brute_force (n<=10) + held_karp (n<=20) + simulated_annealing
# mode = "large": held_karp (n<=20) + simulated_annealing only
./reference_solution graph.json queries_small.json output_small.json small
./reference_solution graph.json queries_large.json output_large.json large
```

Needs the [nlohmann/json](https://github.com/nlohmann/json) single-header
`json.hpp` on the include path (same dependency `driver.cpp` already uses).

## Note on Week 4/5 test data

While building this, I noticed the existing `Week 4/Tests` and `Week 5/Tests`
`output_*.json` files were generated by summing only *direct* edge weights
along each tour, not full Floyd-Warshall shortest-path distances between
subset nodes — even though both READMEs instruct using shortest-path
distances. On the sparse 7-node test graph this understates how good the
true optimal tour can be (e.g. the query on nodes `[0,1,3,4,5,6]` is listed
as costing 33, but the FW-collapsed optimum is actually 30, since node 2
offers a shortcut between 0 and 1 that a "direct edges only" tour can't use).

Week 6's own test data (reusing that same graph for `Test 1`) was
regenerated correctly, so `Test 1`'s numbers won't match Week 4/5's numbers
for the same queries. Flagging this in case you want Week 4/5 fixed too —
happy to patch those if you'd like.
